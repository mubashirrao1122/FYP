1. COLOR SCHEME AUDIT — THE CORE PROBLEM
================================================================================

The application currently uses THREE competing accent color families.
This is the single biggest design problem in the entire app.

  Color Family A:  #2DD4BF / #22C1AE  (Teal/Cyan)
  Color Family B:  #8B5CF6 / #7C3AED  (Tailwind Purple/Violet)
  Color Family C:  #9945FF / #14F195  (Official Solana brand purple + green)

WHERE EACH IS USED:
  - Teal (#2DD4BF): HomeView buttons, Navbar active state, PoolsView, Rewards,
                     CreatePool, focus rings in pools, APY numbers, status dots
                     → Used in 50+ locations

  - Purple (#8B5CF6): SwapTab, BuyTab, SellTab, LimitTab swap buttons,
                       tabs component, input focus rings, token-select borders,
                       TransactionStatus, pool cards, TradingChart loaders
                       → Used in 30+ locations

  - Solana (#9945FF + #14F195): globals.css variables, TokenIcons SVGs,
                                 solana-gradient utility, chat page
                                 → Used in 15+ locations

PROBLEM: A user on the home page sees teal buttons. They click "Launch App",
go to the swap page, and see purple buttons. They open the chat, and see
Solana gradient (purple→green). This feels like 3 different apps.


2. COLOR SCHEME RECOMMENDATION
================================================================================

OPTION A — Commit to Teal (#2DD4BF) as the single primary action color
  Pros: Already dominant on home page and pools/rewards. Reads as "fintech".
        High contrast on dark backgrounds. Unique — most DEXes use blue/purple.
  Cons: Loses Solana branding. Teal-on-dark can feel "cold" without warmth.
  What to change: Replace all #8B5CF6 with #2DD4BF across trading components.

OPTION B — Commit to Solana Purple (#9945FF) as the single primary
  Pros: On-brand for Solana ecosystem. Users immediately associate with SOL.
  Cons: Purple is overused in DeFi (Uniswap, Phantom, Jupiter). Less unique.
  What to change: Replace all #8B5CF6 and #2DD4BF with #9945FF.

OPTION C (RECOMMENDED) — Teal primary + Solana as accent, drop #8B5CF6
  Primary CTA color:     #2DD4BF (teal) — for all buttons, active states
  Accent/Brand:          #9945FF (Solana purple) — for logos, gradients, badges
  Success/Positive:      #14F195 (Solana green) — for profit %, positive changes
  Danger/Negative:       #F87171 — for loss %, sell signals
  Neutral text scale:    #E5E7EB / #9CA3AF / #6B7280 / #4B5563
  DELETE entirely:       #8B5CF6 and #7C3AED — these are generic Tailwind
                         purples that clash with both teal and Solana purple

  WHY THIS WORKS:
  - Teal (#2DD4BF) is distinctive — no other major DEX uses it as primary
  - Solana purple appears only in branding moments (logos, gradients)
  - Green (#14F195) is reserved for financial "positive" signals only
  - No more "two purples fighting each other" problem
  - The palette reads: "premium fintech on Solana" not "generic DeFi clone"


3. BUTTON AUDIT
================================================================================

ISSUE: Buttons use 4+ different styling approaches across the app.

  HomeView buttons:     Inline Tailwind classes, teal rounded-lg, h-10/h-11
  Trading buttons:      Inline Tailwind classes, purple rounded-xl, h-12
  Pool buttons:         Mix of ShadCN <Button> with teal overrides
  ShadCN default:       button.tsx uses bg-primary (oklch theme vars)
  Chat page:            Inline solana-gradient on send button

RECOMMENDATIONS:
  a) Define 3 button variants in button.tsx (not inline styles everywhere):
     - "primary": bg-[#2DD4BF] text-[#0F172A] — main CTA
     - "secondary": border border-white/10 bg-transparent — secondary action
     - "ghost": no border/bg, hover highlight — tertiary action
  b) Use consistent border-radius: rounded-lg everywhere (not mix of xl, md, lg)
  c) Use consistent heights: h-10 (compact), h-11 (default), h-12 (large)
  d) Remove all inline bg-[#8B5CF6] from trading components

5. TYPOGRAPHY AUDIT
================================================================================

  Current font: Inter (--font-inter from layout.tsx)
  
  ASSESSMENT: Inter is acceptable for a financial application — it has
  excellent tabular numbers and is highly readable. While the frontend-design
  skill flags Inter as "generic," for a trading platform, clarity > novelty.
  
  RECOMMENDATIONS:
  - Keep Inter as the primary font — it is the right choice for financial data
  - Consider adding JetBrains Mono or IBM Plex Mono for price displays
    and tabular data (amounts, percentages, addresses) — this adds
    personality without sacrificing readability
  - Ensure all numeric displays use tabular-nums (most already do — good)


6. SPACING AND LAYOUT AUDIT

7. DARK MODE AUDIT
================================================================================

  + Excellent dark mode implementation with explicit color tokens
  + Background hierarchy is clear: #0B1220 → #0F172A → #111827 → #121826
  - Multiple near-identical dark backgrounds (#111827 vs #121826 vs #0F172A)
    creates subtle inconsistency. Simplify to 3 levels:
      Level 0 (page bg):  #0B1220
      Level 1 (cards):    #111827
      Level 2 (inputs):   #1F2937
  - Light mode is clean (#F8FAFC → #FFFFFF → #F1F5F9)


8. ACCESSIBILITY ISSUES
================================================================================

  - Teal (#2DD4BF) on dark backgrounds (#0F172A) — contrast ratio 8.2:1 ✓
  - Purple (#8B5CF6) on dark backgrounds — contrast ratio 4.6:1 — borderline
  - White text on teal buttons — contrast ratio 3.1:1 — ✗ FAILS WCAG AA
    for normal text. FIX: Use #0F172A (dark text) on teal buttons (already
    done in HomeView, but NOT in PoolsView where "text-white" is used)
  - Gray text (#6B7280) on dark bg (#111827) — ratio 3.8:1 — borderline
  - All buttons should have visible focus outlines (most do)
